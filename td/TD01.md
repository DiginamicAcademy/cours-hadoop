## Introduction MapReduce — debug local

Avant de lancer le moindre job sur le cluster (EX 04), une habitude à prendre : **tester mapper et reducer en local**, avec des pipes Unix. Voici le principe et trois variants de la même commande.

> ⚠️ **Ce n'est pas un vrai MapReduce.** Ici, **aucun Hadoop, aucun cluster** : ce sont des **pipes Unix** qui simulent le pipeline. C'est uniquement un **moyen de debug** — vérifier que le mapper émet ce qu'on attend, que le reducer compte juste — **avant** de soumettre le job sur Hadoop. Sur le cluster, c'est Hadoop qui trie et achemine les données jusqu'au reducer ; en local, c'est `sort` qui le remplace.
>
> **Deux commandes Python selon la machine** : **Windows** → `python` · **Linux / MacOS** → `python3`.

### Les deux scripts fournis

Créez ces deux fichiers dans votre répertoire de travail (vous les retrouverez tels quels dans l'EX 04).

`mapper.py` — lit chaque ligne, découpe les mots, émet une paire `mot\t1` :

```python
import sys

for line in sys.stdin:
    for word in line.strip().split():
        print(word.lower() + "\t1")
```

`reducer.py` — lit les paires **triées par clé**, additionne les comptes d'un même mot :

```python
import sys

current = None
total = 0

for line in sys.stdin:
    word, count = line.strip().split("\t")
    count = int(count)
    if word == current:          # même mot : on additionne
        total += count
    else:                        # nouveau mot : on imprime le précédent
        if current:
            print(current + "\t" + str(total))
        current = word
        total = count

if current:                      # ne pas oublier le dernier mot
    print(current + "\t" + str(total))
```

### Tempo A — guidé : trois variants de pipe

Lancez, observez, comparez :

```bash
# 1. Le mapper seul : on voit les paires émises
echo "bonjour bonsoir bonjour bonsoir" | python3 mapper.py

# 2. Mapper + reducer, SANS tri : que se passe-t-il ?
echo "bonjour bonsoir bonjour bonsoir" | python3 mapper.py | python3 reducer.py

# 3. Mapper + sort + reducer : simulation du shuffle
echo "bonjour bonsoir bonjour bonsoir" | python3 mapper.py | sort | python3 reducer.py
```

- Le variant **1** montre la sortie brute du mapper : chaque mot, suivi de `\t1`.
- Le variant **2** sort **exactement comme le mapper** : les clés n'arrivent jamais deux fois de suite (`bonjour, bonsoir, bonjour, bonsoir`), le reducer imprime chaque ligne dès qu'il change de mot — `bonjour\t1`, `bonsoir\t1`, `bonjour\t1`, `bonsoir\t1`. Le regroupement des clés n'a pas eu lieu, le comptage est faux.
- Le variant **3** est le bon : le `sort` **regroupe et trie les clés**, exactement comme le shuffle le fera sur le cluster — le reducer obtient `bonjour\n1\n1\n1\n1` et compte correctement. **Si ça marche avec `| sort |`, ça marchera sur le cluster.**

> **Sous Windows** (avant de se connecter au master) : `type fichier.txt | python mapper.py | sort | python reducer.py` — et usez `python`, pas `python3` (`echo` sous cmd ajoute des guillemets au texte, préférez un fichier).

### Tempo B — entraînement libre

> **Consignes** : en solo ou en binôme, sans support. Les réponses ne se « regardent » pas, elles se **vérifient en lançant les commandes** vous-même.

**Q1.** Quelle est la différence de sortie entre `mapper | reducer` (variant 2) et `mapper | sort | reducer` (variant 3) — et pourquoi la première est-elle fausse ?

**Q2.** Sur le cluster Hadoop, quelle étape du pipeline fait exactement le travail du `sort` du shell ici ?

### Pour aller plus loin — le CSV Spotify

Réutilisez les deux squelettes pour obtenir le **total des streams par année**, directement à partir du CSV du cours.

- **Mapper** : lire `../data/Spotify_Most_Streamed_Songs.csv`, extraire l'année (`released_year`, colonne 3) et les streams (`streams`, colonne 8), émettre `année\tstreams`.
- **Reducer** : quasiment inchangé — c'est toujours « additionner les valeurs d'une même clé ».
- ⚠️ **L'en-tête** : la première ligne ne doit pas compter (sinon `released_year` devient une « année »).
- ⚠️ **Ligne 576** : le champ `streams` est **corrompu**. Sans protection, `int()` plante — et le test local le montre **immédiatement**. C'est exactement l'intérêt de ce debug : trouver la panne avant le cluster.

```bash
# Linux / MacOS
cat data/Spotify_Most_Streamed_Songs.csv | python3 mapper_spotify.py | sort | python3 reducer.py

# Windows
type DATA\Spotify_Most_Streamed_Songs.csv | python mapper_spotify.py | sort | python reducer.py
```

**À conserver dans le rapport** : les 5 premières et les 5 dernières lignes de la sortie (une ligne `année\ttotal` par année), et une phrase sur ce que le variant 2 a laissé paraître.
