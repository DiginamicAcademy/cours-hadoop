## Introduction — la question remplace le traitement

Au TD01 vous avez *écrit le traitement* (mapper `|` sort `|` reducer). **Ici, un moteur l'écrit à votre place : vous posez la question (SQL), Hive fait le reste.** Ce TD ne fait que le *voir fonctionner* sur le vrai cluster — le « comment » (compilation en job MapReduce, types, `EXPLAIN`) est le programme de la séquence 05.

> 🗂️ **Gardez sous la main** : votre sortie « streams par année » du [TD01](TD01.md) et le total de `streams` de l'[EX 04](../exercices/04-mapreduce.md) (**489 458 828 542**) — on les comparera à la fin.

### Tempo A — guidé : une table, quatre requêtes

> Tout se passe dans le conteneur master (`hadoop-master`). Les durées sont des ordres de grandeur : la première connexion Beeline peut prendre ~30 s (Metastore Derby).

Vous aurez besoin de 2 terminals :
- le premier pour Hive (a exec depuis master)
- le second pour les autre commandes depuis master

**1. Connectez-vous** avec le premier terminal. Si HiveServer2 n'est pas lancé : `./start-hive.sh`. Puis :

```bash
beeline -u jdbc:hive2://localhost:10000
```

> Si `beeline: command not found` : `export PATH=$PATH:/opt/hive/bin`, ou tapez le chemin complet `/opt/hive/bin/beeline -u jdbc:hive2://localhost:10000`. Le prompt `0: jdbc:hive2://…>` remplace le shell.

**2. Montez la base et la donnée** avec le second terminal. Préparez le TSV (script fourni) et déposez-le dans HDFS :

```bash
python3 7-prepare-spotify-tsv.py Spotify_Most_Streamed_Songs.csv spotify-clean.tsv
wc -l spotify-clean.tsv          # 954 : l'en-tête + 953 titres
hdfs dfs -mkdir -p /user/root/spotify/clean
hdfs dfs -put -f spotify-clean.tsv /user/root/spotify/clean/
```

**3. Déclarez une table externe** avec le premier terminal. La DDL est **fournie** — recopiez-la telle quelle (les backticks autour de `key` sont obligatoires). C'est votre « mapper » : décrire l'entrée, pas l'algorithme.

```sql
 CREATE DATABASE spotify_db;
 USE spotify_db;

CREATE EXTERNAL TABLE spotify (
  track_name STRING, artist_name STRING, artist_count INT,
  released_year INT, released_month INT, released_day INT,
  in_spotify_playlists INT, in_spotify_charts INT,
  streams BIGINT, in_apple_playlists INT, in_apple_charts INT,
  in_deezer_playlists STRING, in_deezer_charts INT, in_shazam_charts STRING,
  bpm INT, `key` STRING, mode STRING,
  danceability_pct DOUBLE, valence_pct DOUBLE, energy_pct DOUBLE,
  acousticness_pct DOUBLE, instrumentalness_pct DOUBLE,
  liveness_pct DOUBLE, speechiness_pct DOUBLE, cover_url STRING
)
ROW FORMAT DELIMITED FIELDS TERMINATED BY '\t'
LOCATION '/user/root/spotify/clean';
```

**4. Comptez tout** avec le premier terminal. Lancez, observez :

```sql
SELECT COUNT(*)      FROM spotify;   -- 954
SELECT COUNT(streams) FROM spotify;  -- 952
```

- `COUNT(*)` vaut **954** : l'en-tête du TSV est **compté comme une chanson**. Hive ne « saute » rien — il fait des lignes de données avec tout ce qu'il lit.
- `COUNT(streams)` vaut **952** : deux lignes ont un `streams` non numérique (l'en-tête `streams='streams'`, et la **ligne 576** au champ corrompu) → Hive les met à `NULL` **sans erreur ni avertissement**. Personne ne vous prévient : à vous de comparer les comptages pour le voir.

**5. La question du TD01, sans le traitement.** Le comptage qu'au TD01 vous obteniez avec `mapper_spotify.py | sort | reducer.py` :

```sql
SELECT released_year, SUM(streams) AS total
FROM spotify
GROUP BY released_year
ORDER BY released_year;
```

Lancez-la et **comparez ligne à ligne avec votre sortie de pipes** : les mêmes années, les mêmes totaux (le premier groupe, `NULL`, c'est l'en-tête — il a « travaillé »). À la ligne 576 près — déjà incognito en `NULL`. Votre pipe et cette requête sont d'accord : **le GROUP BY est le sort du pipeline, écrit par le moteur.**

**6. (Si déjà fait à l'EX 04) Le top des artistes.** Même principe, autre clé :

```sql
SELECT artist_name, SUM(streams) AS total
FROM spotify
GROUP BY artist_name
ORDER BY total DESC
LIMIT 6;
```

Six lignes. Comparez aux six clés de tête de votre `part-00000` de l'EX 04 (artistes) — **chiffre pour chiffre**.

### Pour aller plus loin — comparer à MapReduce

- Rejouez le stream/année du TD01 en pipes **à côté** de la requête Hive : les deux sorties doivent coller ligne à ligne. C'est la validation croisée que l'EX 05 exige à plus grande échelle.
- Regardez le plan de la requête : `EXPLAIN SELECT artist_name, SUM(streams) FROM spotify GROUP BY artist_name;` — vous y reconnaîtrez les **stages Map/Reduce**. Le moteur a écrit votre mapper/reducer.
- Comptez les groupes rendus par le `GROUP BY released_year` (`SELECT COUNT(*) FROM (SELECT DISTINCT released_year FROM spotify) t;`) : **51**, pas 50. Lequel est l'intrus, et d'où vient-il ?
