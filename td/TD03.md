## Introduction — lire quelque chose par sa clé

Au [TD02](TD02.md), Hive a répondu « total des streams par année » : le moteur lit en vrac et regroupe lui-même. HBase répond à **l'autre besoin** : « donne-moi **cette ligne-là**, tout de suite ». Pour ça, chaque ligne a une **clé** (`rowkey`) — et cette clé va vous surprendre **avant même le cours**.

> ⚠️ **C'est du vrai HBase, avec le vrai shell.** Comme au TD02, le but n'est pas d'expliquer la mécanique (régions, WAL, MemStore — c'est la séquence 06) mais de **voir** ce que promettent ces deux principes : *la table est triée par clé* et *le `put` ne confirme rien*.

## Tempo A — guidé : une table, des `put`, un `scan`

> Tout se passe dans le conteneur master (`hadoop-master`). Si HBase n'est pas démarré : `./start-zookeeper.sh` puis `./start-hbase.sh` (il l'est si vous avez fait `./start-all.sh`).

**1. Ouvrez le shell HBase.**

```bash
hbase shell
```

Le prompt `hbase:001:0>` remplace le shell.

**2. Créez une table** avec une famille de colonnes `stats` :

```bash
create 'chrono', 'stats'
```

HBase répond `0 row(s)` aussi pour « table créée »… vous en tirerez la leçon à l'étape 4.

**3. Insérez trois lignes, dans un ordre volontairement farfelu** — chaque ligne porte le total des streams d'une année (chiffres du [TD02](TD02.md)) :

```bash
put 'chrono', '2023', 'stats:total', '25808484104'
put 'chrono', '1975', 'stats:total', '4206105352'
put 'chrono', '2021', 'stats:total', '73808103039'
```

Observez la réponse de chaque `put` : `0 row(s) in 0.… seconds`. Notez bien ce « 0 row(s) ».

**4. Lisez tout : `scan`.**

```bash
scan 'chrono'
```

**Observez l'ordre des lignes.** Vous avez inséré `2023`, puis `1975`, puis `2021` — regardez dans quel ordre le `scan` les rend : `1975`, `2021`, `2023`. La table **n'est pas vide** (les 3 `put` ont écrit), mais elle est **triée par clé**, pas par ordre d'arrivée. Le « 0 row(s) » des `put` ne signifiait donc pas grand-chose.

**5. Lisez une ligne précise : `get`.**

```bash
get 'chrono', '1975'
```

Une seule ligne, ses colonnes et valeurs. C'est la promesse de HBase : **retrouver directement** une ligne par sa clé, sans tout lire.

## Tempo B — entraînement libre

> **Consignes** : en solo ou en binôme, sans support. Les réponses se **vérifient en relançant les commandes** vous-même.

**Q1.** Vous avez `put` `'2023'` en premier (puis `'1975'`, puis `'2021'`). Le `scan` les affiche `1975, 2021, 2023`. Quelle règle décide de l'ordre — et pourquoi `2023` n'est pas premier malgré sa première insertion ?

**Q2.** Chaque `put` a répondu `0 row(s)`. A-t-il écrit ? Quelle est la **seule preuve** que les données sont là ?

**Q3.** La règle de tri des rowkeys vous rappelle une étape du TD01/du shuffle MapReduce. Laquelle, et pourquoi Hive (TD02) et HBase affichent-ils leurs années dans le *même* ordre croissant que le `sort` de vos pipes ?

## Tempo C — HappyBase : HBase depuis Python

> Le shell HBase est pratique pour explorer, mais en production on appelle HBase depuis un programme. **HappyBase** est une bibliothèque Python qui fait exactement la même chose que le shell — `put`, `scan`, `get` — depuis du code Python.

**1. Lancez le ThriftServer** (depuis le master) :

```bash
./start-thrift.sh
```

Vérifiez que le service tourne :

```bash
jps | grep Thrift
```

> Le ThriftServer est le pont entre Python et HBase. Sans lui, la connexion échoue.

**2. Ouvrez un terminal Python** (toujours dans le master) et importez la bibliothèque :

```python
import happybase
```

**3. Connectez-vous et accédez à la table `chrono`** :

```python
connection = happybase.Connection('127.0.0.1', 9090)
table = connection.table('chrono')
```

**4. Insérez les mêmes lignes que le Tempo A** :

```python
table.put('2023', {'stats:total': '25808484104'})
table.put('1975', {'stats:total': '4206105352'})
table.put('2021', {'stats:total': '73808103039'})
```

> Même `put`, même « rien en retour » — HBase ne confirme pas, que ce soit via le shell ou Python.

**5. Scannez la table** :

```python
for key, data in table.scan():
    print(key, data)
```

**Observez le résultat** : même ordre trié que le shell (`1975`, `2021`, `2023`). Les données sont identiques, quelle que soit l'outil utilisé.

**6. Lisez une ligne précise** :

```python
print(table.row('1975'))
```

> Même résultat que `get 'chrono', '1975'` dans le shell.

**7. Fermez la connexion** :

```python
connection.close()
```

## Pour aller plus loin — trier, lire un intervalle, versionner

- **Un intervalle de clés** : lisez les années entre deux rowkeys :

  ```bash
  scan 'chrono', { STARTROW => '1975', STOPROW => '2021' }
  ```

  « Donne-moi ce bloc-là » — la lecture par plage de clés, au lieu de tout relire. (Comparez : pour faire *avant/après* une année au TD02, il fallait trier puis filtrer. Ici la clé **contient déjà l'ordre**.)

- **La date cachée** : relisez un `scan` en entier — chaque cellule porte un `timestamp`. Refaites le *même* `put` (`2021`), rescannez : la valeur est remplacée, le `timestamp` a changé. HBase ne corrige pas, il **versionne**.

- **Le goutte à goutte des 50 années** : rechargez la table `chrono` avec les 50 années du TD02 (`put` dans une feuille) puis comptez les lignes du `scan` — vous retrouverez les 50 groupes du `GROUP BY released_year`.

**À conserver dans le rapport** : la sortie du `scan` étapes 4-5 (shell), la sortie du `scan` étape 5 (Python), et une phrase sur le « 0 row(s) » (la preuve n'est pas la réponse du `put`).
