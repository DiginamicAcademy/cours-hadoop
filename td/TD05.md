## Introduction — la répétition générale

Vous avez travaillé sur le CSV Spotify depuis cinq jours : mapper, reducer, HDFS, Hive, HBase, NiFi. À chaque fois, la commande est la même — ce qui change, c'est la **question** posée à la donnée. Le TP final garde le même CSV (953 chansons) et la même chaîne ; il ne demande plus « combien de streams par année ? » mais « **quels artistes** cumulent le plus de streams ? ».

Ce TD vérifie en 15 minutes, **sur votre poste et sans cluster**, que la chaîne répond à cette question-là : mapper → tri → reducer, puis le même classement en SQL. C'est la condition pour lancer le TP — si le pipe passe ici, il n'y aura rien à réécrire sur le cluster.

## Tempo A — guidé : la chaîne complète, en local

Les commandes se lancent **depuis la racine du dépôt** (là où se trouvent `data/` et `annexes/`).

**1. Lancez le mapper sur le CSV Spotify :**

```bash
cat data/Spotify_Most_Streamed_Songs.csv | python3 annexes/utils/8-mapper-streams-artiste.py | head -5
```

**Ce que vous observez** : chaque ligne contient une **clé** (l'artiste) et une **valeur** (les streams), séparées par une tabulation. Comparez au header : `artist(s)_name` est à la colonne 1, `streams` à la colonne 8 — le mapper extrait exactement ces deux champs. Notez la première ligne : `Latto, Jung Kook` — une collaboration avec une virgule, et **une seule** clé.

> 📎 Si python affiche un `BrokenPipeError` en rouge, ce n'est pas le mapper qui a échoué : c'est `head` qui a fermé le tube pendant qu'il écrivait encore. Le même réflexe vaut pour tout pipe `| head`.

**2. Combien de lignes sort-il ?**

```bash
cat data/Spotify_Most_Streamed_Songs.csv | python3 annexes/utils/8-mapper-streams-artiste.py | wc -l
```

**952** — pas 953. Le fichier contient 953 chansons ; le mapper en écarte une. Regardez-la de près :

```bash
sed -n '576p' data/Spotify_Most_Streamed_Songs.csv
```

C'est `Love Grows (Where My Rosemary Goes)` : son champ `streams` ne contient plus un nombre, mais les colonnes numériques d'après collées bout à bout (`BPM110KeyAModeMajor…`). Le `try/except` du mapper l'ignore ; sans lui, **le job échoue**. Retenez ce numéro de ligne : le TP vous demandera de rejouer l'expérience.

**3. Pipez dans le reducer, puis classez par valeur :**

```bash
cat data/Spotify_Most_Streamed_Songs.csv | python3 annexes/utils/8-mapper-streams-artiste.py \
  | sort -t $'\t' -k1,1 \
  | python3 annexes/utils/10-reducer-somme.py \
  | sort -t $'\t' -k2,2nr | head -5
```

**Résultat attendu** : une ligne par artiste avec ses streams cumulés, et le podium en tête.

```text
The Weeknd      14185552870
Taylor Swift    14053658300
Ed Sheeran      13908947204
Harry Styles    11608645649
Bad Bunny        9997799607
```

Le premier `sort` trie **par clé** (`-k1,1`) : c'est ce que le reducer attend — les valeurs d'une même clé doivent arriver consécutivement. Le second trie **par valeur** (`-k2,2nr`) pour faire apparaître le podium : c'est un tri de *lecture*, pas un maillon du calcul.

**4. Même résultat, en SQL (sqlite3) :**

```bash
sqlite3 :memory: <<'EOF'
.mode csv
.import --csv data/Spotify_Most_Streamed_Songs.csv spotify
.mode column
.headers on
SELECT "artist(s)_name" AS artiste, SUM(streams) AS total
  FROM spotify GROUP BY 1 ORDER BY total DESC LIMIT 5;
EOF
```

Les cinq premiers artistes et leurs totaux sont **les mêmes** que dans le pipe. Le même résultat, deux chemins — c'est exactement la vérification que le TP vous demandera (Q1 MapReduce contre Q3 Hive).

Deux détails à relever. `.import --csv` lit le fichier **comme du CSV** — les guillemets sont gérés, `Latto, Jung Kook` reste **un** artiste — et il se sert de la première ligne comme noms de colonnes : `SELECT COUNT(*) FROM spotify;` rend donc **953**, pas 954. Et `SELECT SUM(streams) FROM spotify;` rend `489458828542` : la ligne 576 y vaut **0**, pas un crash.

> `.import --csv` existe depuis sqlite 3.32 — vérifiez avec `sqlite3 --version`.

## Pour aller plus loin

- **Comparaison HBase** : les rowkeys d'une table HBase sont triées **octet par octet**, alors que votre `sort` local trie selon la locale. Reprenez le pipe avec `LC_ALL=C sort -t $'\t' -k1,1` : la première ligne n'est plus `21 Savage, Gunna` mais `(G)I-DLE`, et la dernière n'est plus `Zion & Lennox` mais `teto`. La ponctuation passe avant les chiffres, et les minuscules après les majuscules — c'est ce choix d'octets qui rend une rowkey rapide (ou lente) à retrouver.
- **Le TP complet** : même fichier, même mapper, mais sur le **cluster** (HDFS → `hadoop jar`), puis Hive (table externe), puis HBase (stockage par artiste), puis NiFi (ingestion automatique), puis Matplotlib (graphique du top 10). La valeur de ce TD est que **rien n'est nouveau** : vous ne faites que connecter des maillons déjà vus.

➡️ **J5 — TP final** : déposez `Spotify_Most_Streamed_Songs.csv` dans HDFS (`hdfs dfs -put`), lancez la même chaîne sur le cluster (mapper → reducer via `hadoop jar`), validez en Hive, stockez en HBase, puis rendez le rapport. Les scripts de ce TD — `8-mapper-streams-artiste.py`, `9-mapper-streams-annee.py`, `10-reducer-somme.py` — sont prêts dans `../annexes/utils/` : si le pipe de ce TD passe, il n'y a rien à réécrire.
