## Tempo A — les trois variants de pipe

### Variant 1 — le mapper seul

```
bonjour	1
bonsoir	1
bonjour	1
bonsoir	1
```

Le mapper émet une paire par occurrence : rien n'est compté, on voit **chaque** mot. `echo` envoie le texte par stdin, `split()` découpe sur tout blanc, le `\t1` est systématique.

### Variant 2 — mapper `|` reducer, SANS tri

```
bonjour	1
bonsoir	1
bonjour	1
bonsoir	1
```

**Idem** que le variant 1. Le reducer suppose que les clés arrivent **regroupées** (même mot d'affilée) ; or ici elles arrivent dans l'ordre d'émission `bonjour, bonsoir, bonjour, bonsoir`. Chaque changement de mot déclenche l'impression de la ligne courante → chaque ligne recrachée telle quelle, **aucun compte n'est additionné**. Le comptage est faux, mais *silencieusement* : le programme ne plante pas, il rend un résultat plausible si on ne connaît pas la bonne réponse.

### Variant 3 — mapper `|` sort `|` reducer : la simulation du shuffle

```
bonjour	2
bonsoir	2
```

Le `sort` **regroupe les clés identiques** : le reducer reçoit les deux `bonjour` d'affilée, puis les deux `bonsoir` → il additionne. C'est la seule variante correcte.

> Règle à garder : **le reducer est à l'arrêt s'il n'a pas son tri.** En local, `sort` ; sur le cluster, c'est Hadoop qui trie et achemine (shuffle + sort). **Si le pipe local `| sort |` fonctionne, le job sur le cluster fonctionnera** — et inversement, un pipe sans tri cache un password de shuffle maladroit.

## Tempo B — réponses

**Q1.** Le variant 2 sort **exactement comme le mapper** (`bonjour\t1, bonsoir\t1, bonjour\t1, bonsoir\t1`) : les clés n'arrivent jamais deux fois de suite, le reducer *recrache* chaque ligne au premier changement de mot. Le variant 3 sort `bonjour\t2, bonsoir\t2` : le `sort` a regroupé les clés. La première est fausse parce que l'**hypothèse du reducer** (« chaque clé arrive en un seul bloc ») n'est pas remplie — le comptage ne porte que sur des groupes de taille 1.

**Q2.** C'est le **shuffle + sort** (la phase qui transporte les paires des mappers vers les reducers, en les **groupant et triant par clé**). En local, le `sort` Unix joue ce rôle de doublure ; sur le cluster, c'est Hadoop qui le fait — le reducer, lui, reste identique de part et d'autre.

**Q3.** La paire `mot\t1` fixe une **interface stable** entre mapper et reducer : le reducer fait `line.strip().split("\t")` et sait que `[1]` est **toujours** le compte. Si le séparateur n'est pas stable (un mot contenant des espaces, une tabulation manquante, une valeur non numérique), le reducer reçoit un champ en trop ou en moins : `split()` casse la ligne en plus/moins de 2 éléments et `int()` lève une exception → `subprocess failed` sur le cluster, ou un comptage faux si on ignore l'erreur. Le job est lancé en parallèle sur des nœuds différents : chaque mapper doit produire **exactement la même convention**, sinon les paires d'un mapper sont illisibles par les reducers de tous les nœuds.

## Pour aller plus loin — total des streams par année

### mapper_spotify.py

```python
import sys
import csv

for row in csv.reader(sys.stdin, delimiter=','):
    if len(row) < 9 or row[0] == 'track_name':   # sauter l'en-tête
        continue
    released_year, streams = row[3], row[8]
    try:
        streams = int(float(streams))            # ligne 576 : protégée
    except ValueError:
        continue
    if released_year.isdigit():                  # '1970' oui, 'released_year' non
        print("%s\t%s" % (released_year, streams))
```

- **L'en-tête** est écarté **par la valeur** (`row[0] == 'track_name'`), jamais par `next()` : sur le cluster, l'en-tête n'existe que dans le premier split (cf. TD 02b).
- **Ligne 576** (*Love Grows (Where My Rosemary Goes)*, 1970) : le champ `streams` contient la moitié des autres colonnes (`BPM110KeyAModeMajor…`). Sans le `try/except`, `int()` lève une exception locale immédiatement — le pipe affiche une erreur (ou un résultat partiel selon le shell). C'est tout l'intérêt du debug local : **la panne se voit avant le cluster**, où elle donnerait `PipeMapRed.waitOutputThreads(): subprocess failed with code 1`.
