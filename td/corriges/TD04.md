## Tempo B — réponses

**Q1.** PutFile utilise l'attribut `${filename}` du FlowFile, c'est-à-dire le **nom original** du fichier lu par GetFile : il le reproduit tel quel. NiFi ne se fie pas à l'extension pour interpréter le contenu — il déplace des octets. C'est un outil qui se fie au nom **qui le lira** qui doit se poser la question : Excel ouvre un `.csv` avec le séparateur virgule, et une colonne contenant `"Latto, Jung Kook"` sera décalée. Hive ne se fie pas au nom ; un tableur si.

**Q2.** Le second FlowFile (même nom) part sur la relation **`failure`** de PutFile. Avec `failure` auto-terminée, il disparaît de la vue du flux. Dans Data Provenance, il apparaît avec le statut **`CONTENT_MODIFIED`** manquant (pas de `SEND` sur PutFile) : il a été **refusé**. Si `failure` n'est pas auto-terminée (câblée vers un PutFile `errors`), le FlowFile reste dans la queue → le compteur de la queue monte : **back pressure**, le flux **se bloque** — c'est pire qu'une erreur visible.

**Q3.** GetFile lit n'importe quel fichier passant le filtre `.*\.csv` : la ligne de texte est captée en FlowFile. PutFile l'écrit dans `/opt/nifi/output` sans la valider : c'est un processeur d'**écriture**, pas de **validation**. La donnée corrompue **sort intacte** du flux. La preuve est dans Data Provenance : le Lineage montre GetFile → PutFile comme pour un fichier valide. NiFi ne traite pas le contenu ici ; c'est le `ConvertRecord` (présent dans l'EX 07) qui vérifierait la structure CSV. Un CSV mal formé irait sur la relation `failure` de ConvertRecord — pas de GetFile ni PutFile.

## Pour aller plus loin

- **Minimum File Size** : sans filtre, tout fichier passe. Avec `Minimum File Size = 100 KB`, le petit fichier de test n'est plus lu par GetFile — le compteur reste à 0. Le premier filtre existe déjà dans le processeur.
- **ConvertRecord** : entre GetFile et PutFile, avec reader/writer configurés, le contenu passé en sortie est du **TSV** (tabulations) — le fichier arrive dans `/opt/nifi/output` converti, prêt pour Hive. Le nom reste `.csv` : la conversion est de contenu, pas de nom.
- **Lien EX 07** : le flux complet (GetFile → ConvertRecord → PutFile → `moveFromLocal` vers HDFS) est exactement celui de l'EX 07. Ce TD en montre le squelette ; l'EX ajoute la gestion des échecs (`failure` câblée) et le renommage via `UpdateAttribute`.
